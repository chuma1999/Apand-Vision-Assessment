## TECHNICAL DECISIONS

1. Why did you choose your programming language and framework?

## Why I chose Javascript and its frameworks?

- JavaScript allows me to build the backend with Node.js/Express and the frontend with JavaScript, keeping the application within one ecosystem.

- Node.js and Express make it straightforward to build REST APIs that communicate efficiently with the PostgreSQL database.

- JavaScript has strong support for real-time technologies such as WebSockets, which could later be used for instant CCTV alerts and live event updates.

- JavaScript has a huge ecosystem of libraries and frameworks, making it easier to integrate databases, authentication, AI services, notifications, and other features.

- Even though the computer-vision component can use Python, JavaScript can act as the main application layer, receiving AI-generated events through APIs and displaying them on the dashboard.

2. Why did you choose your database?

## why I chose PostgreSQL

- PostgreSQL is a mature relational database suitable for storing CCTV events reliably.

- CCTV events have clear relationships and fields such as camera, location, event type, timestamp, and status, which fit well with a relational database.

- PostgreSQL can efficiently handle large numbers of events generated by multiple cameras.

- It can grow with the system as more cameras, events, users, and AI-generated data are added.

- PostgreSQL integrates easily with Node.js and Express through the pg library, making database communication straightforward.

3. How did you structure the application?

- Separated frontend and backend: The frontend handles the CCTV dashboard, while the Node.js/Express backend handles API requests and database communication.

- Used REST API architecture: The frontend communicates with the backend through /api/events, keeping the application organized and allowing other services, such as AI, to integrate later.

- Separated database logic: PostgreSQL is responsible for permanently storing CCTV events, while the backend retrieves the data when needed.

- Designed for future AI integration: The structure allows a separate Python AI service to analyse camera footage and send detected events to the backend.

9.  What would you change if this became a real production system?

- Improve security: Add authentication, authorization, HTTPS, secure environment variables, and restrict access to camera streams and APIs.

- Separate the AI service: Run the computer-vision system as a dedicated Python service so AI processing does not affect the main Node.js application.

- Add real-time communication: Use WebSockets or Server-Sent Events so new CCTV events appear on the dashboard immediately instead of relying only on polling.

- Improve reliability and scalability: Use Docker, health checks, proper logging, database backups, and potentially Redis/message queues to handle large numbers of cameras and events.

- Add proper event management: Store AI confidence, snapshots/video clips, detection history, and timestamps, while adding rules to reduce false detections and duplicate alerts.
